# 資格試験「マンション攻略」学習サイトの設計ロジック

実際に運用している「William の部屋」（管理業務主任者試験、308 問）で、利用者と何十回も調整して決まった設計をまとめたもの。新しい資格サイトを作るときも、既存サイトを直すときも、まずここに沿う。細かい数値やファイル形式は `references/` を読む。

## 0. 作業の進め方（いちばん大事）

利用者は時間とトークンを使わされることを最も嫌う。
- **不満を言われたら、数値をいじる前に「どの段階で間違えたか」を決める**（要件の理解／作り方・構造／パラメータ）。構造が原因なら微調整を重ねず、元から作り直す。自分の力や道具では無理なら、何を借りるべきか（画像生成、外部ツール、人の手）をはっきり言う。
- 直したら、**自分でスマホ幅とPC幅のスクリーンショットを撮って確かめてから**見せる（Playwright、`deviceScaleFactor: 1` で十分）。アニメーションは止めて時間指定でコマを取る（`getAnimations()` → `pause()` → `currentTime`）。
- 返事は短く。報告の最後に、毎回 本番の確認リンク（ユーザーごとのテストリンク）を付ける。
- 大量のコンテンツ（ヒント、要点、章立て）は、年度や章ごとにサブエージェントへ並行で書かせ、**元の解説にある事実だけ**を使わせ、件数・ID の網羅を Python で検証してから取り込む。自動マージは意味の違う行をまとめることがあるので、数字の行は目で確認する。

## 1. 世界観と画面構成

- **マンション＝試験全体**。階＝出題分野（1F〜8F）、部屋（窓）＝同じテーマの問題 5〜8 問のまとまり、窓の明かり＝その部屋の 8 割に正解（`need = ceil(n*0.8)`）。全室点灯で階に★。
- **相談票＝問題カード**。管理人（マスコット）が相談を持ってくる体裁。答えたら全選択肢に ○×と理由、組合せ問題は ア〜エ の文ごとに ○×と理由、根拠条文、法改正の注意。
- **マスコット猫**（Live2D、例：Tororo モデルのテクスチャだけ差し替え）。形・メッシュは変えない。
- PC：左 3 割＝マンション（索引）、右 7 割＝部屋（相談票＋猫）。スマホ：①マンション画面 → 窓をタップ → ②部屋画面（`history.pushState` で端末の「戻る」が効く）。縦持ちタブレットはスマホ扱い。
- 夜空のマンション絵の**月**が「まとめノート」の入口。月は文字を出さず、光の強弱＋光の輪＋小さな星で「押せる」と伝える。特効は屋根の後ろに回す（屋根部分だけ同じ絵を上に重ねる）。

## 2. 学習の流れ

1. 問題を解く → すぐ解説。正解・不正解の効果音とマスコットの一言（少なめ）。
2. 長く考えていると **ヒント 3 段階**（30 秒・1 分・2 分）。答えは言わず、考える方向だけ。猫が寝ているときは「寝言」吹き出し。
3. 部屋が 8 割正解で **点灯**：青い帯のカットイン「点灯!!」に、飼い主の猫の**実写真**をポラロイド風に（ランダム、連続で同じ写真は出さない）。全問正解は「まじ!!」。その後のパネルはカギの絵。
4. まちがえた問題は**要復習**になる（`box` による間隔復習 1・3・7・14・30 日も持つ）。
5. **まとめノート**（月から）：知識マップ → 再テスト → チートシート。

## 3. まとめノート（チートシート＋知識マップ＋再テスト）

- **知識マップ**：中心＝月（「要復習の部屋」の数）→ 階 → 部屋の放射状グラフ（一覧表示と切替）。状態は 4 つ：
  - 要復習（光る：どれか最後にまちがえた／復習途中）、**克服（緑＋✓：まちがえた問題を全部克服）**、習得（暗い：点灯して要復習なし）、まだ（点線）。
  - 光は**ごく弱く・止める or 全ノード同位相**。まぶしい・バラバラな点滅は不可。赤い数字バッジは最上層（隣のノードに隠れない）。スマホ実寸で文字が読める大きさ（viewBox 800 なら部屋番号 19 以上）。
  - 部屋を押す → その部屋の要点まで、階を押す → その章まで。止まる位置は**固定ヘッダーの実寸を測って、その直下 8px**。
- **再テスト**：上部の大きなボタン。要復習からランダム 10 問（5／10／全部の選択と、×の多い問題優先が推奨案）。1 問ずつ、答えたらその場で記録し**正解＝克服**。途中でやめても克服は残り「克服 n 問を記録しました」。結果画面に「まだの問題をもう一度」。
- **チートシート**（2 つの切替）：
  - まちがえた問題のポイント：**克服しても外さない**（要復習が上、克服は下に札）。カードの主役は**知識のポイント 2〜4 行の箇条書き**。問題文と答えは「問題と答えを見る」にたたむ（中では全文＋各選択肢の ○×と理由＋前回の答え）。
  - 全体の復習ポイント：**市販テキストの章・節の順**（問題の階・部屋の順ではない）。重複する要点は 1 行にまとめ、出典の問題番号を並べる。要復習に関わる行は ★。
- **色分け**（凡例を出す）：黄マーカー＝最重要（`**…**`）、青＝数字・期限、赤＝否定・禁止、橙＝例外、赤札「ひっかけ注意」＝「〜ではない」で区別させる行。自動判定なので外れることがあると伝える。
- 右端に**自前のスクロールバー**（つまみ・溝タップ・ドラッグ中に章・節名、章の目盛り）と「▲ マップへ」ボタン。
- 遷移：月 → マップ中心の月へ飛ぶ（共有要素遷移）、戻るときは逆。`prefers-reduced-motion` では動かさない。

## 4. マスコットのふるまい（うるさくしない）

- 自分から話すのは 3 分以上あけ、15 分に 2 回まで。答えへのコメントは 25 秒に 1 回まで。夜は 10〜15 分。休憩の声かけ 40 分。
- **苦手分野を指摘しない**（504 号室にいるときに 303 号室の話をしない、空気を読む）。苦手部屋への誘導はボタンだけ。
- 試験日のカウントダウンを画面に出さない。猫が 1 日 2 回まで、3 時間以上あけて、夜は言わない、やさしい言い方で。
- 吹き出しはタップで消える。問題文と重ならない位置。かわいい猫語のみ（物騒な言葉は使わない）。

## 5. 記録と同期

- 記録は**答えるたびに**ブラウザ（localStorage）へ保存し、同期サーバーへ 50ms 後に送る。各問題：`a`（回答数）`c`（正解数）`last` `t` `p`（選んだ番号）`box` `due`。
- ほかの端末の記録と合わせるときは **このブラウザ優先、サーバー側の回答数が多いときだけサーバー側**。今いる場所もこのブラウザ優先。
- 進度リンク：`?u=<推測されにくい ID>` で端末をまたいで同じ記録。サーバー URL は リポジトリの `tunnel.json` から読む（住所が変わってもリンクは不変）。記録をリンクに埋め込む「記録のリンク」もサーバー無しのバックアップとして用意。
- サーバーは利用者の PC（LocalServer、Tailscale Funnel やトンネル）か Cloudflare Workers＋KV。**利用者が禁止したサービス（例：Supabase）は使わない**。書き込みに鍵は無いので、ID とリンクは他人に教えない。

## 6. 文字・レイアウトの決まり

- **文字は絶対に重ねない**（月のラベル、バッジ、カットインの写真と見出し、吹き出しと問題）。孤立した 1 文字の改行も不可 → 説明文を削るか別の行へ。
- 文字の上に模様を置かない（クレーターは文字の後ろから外す、縁取り `paint-order: stroke`）。
- 光・点滅はまぶしくしない。キラキラは要求されたところだけ。
- アニメーション名は既存と衝突させない（同名 `@keyframes` で背景の星を止めた事故あり）。`transform` を使うアニメに傾きを足すときは独立プロパティ `rotate` / `translate` を使う。

## 7. 実装の形

- `src/data/kakomon/<年度>.json`（問題・選択肢・答え・解説・選択肢ごとの解説・根拠・法改正・要確認）、`rooms.json`（部屋割り）、`hints/`、`points/`、`syllabus/`（章 → 節 → 要点＋出典 ID）、`drills/`。
- `build.py` が テンプレート 1 枚（`tpl.html`）にデータと画像（data URI）を埋め込み、`public/index.html` を出力。GitHub Pages へデプロイ。画像は CSS 変数で 1 回だけ埋め込む。
- 設計の考え方（没入 × 専門性）と協作のしかたは スキル `immersive-study-design` に。両方いっしょに使う。
- 詳しいデータ形式とビルドの約束は `references/data-and-build.md`、まとめノートの判定式は `references/review-logic.md`。
